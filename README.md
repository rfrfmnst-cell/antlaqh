# منصة انطلاقة — الإصدار 5

مشروع جديد للخدمات والمنتجات الرقمية، بواجهة عربية تدعم الجوال، وحساب عميل ولوحة إدارة. يحفظ الخادم الطلبات والموافقات والدفعات والملفات الخاصة، ويمنع وصول العميل إلى بيانات الآخرين.

## ما يتضمنه المشروع

- صفحات الخدمات، «ابدأ مشروعك»، التعريف بالمنصة، المتجر، الشروط والخصوصية.
- تسجيل حساب ودخول بالبريد وكلمة المرور، جلسات آمنة، تغيير كلمة المرور وإلغاء الجلسات الأخرى.
- توثيق الجوال والدخول برمز للجوال الموثق عند إعداد Twilio Verify.
- طلبات خدمات مرتبطة بصاحب الحساب، رسائل ومرفقات وسجل مراحل.
- عروض أسعار وعقود ذات إصدارات مستقلة وموافقة مؤرخة من العميل.
- تأكيد دفع يدوي من الإدارة، إيصال قابل للطباعة، وإلغاء استحقاق موثق.
- إدارة منتجات رقمية: مسودات، ملف تسليم، نشر وإخفاء وتعديل.
- لا يُعرض منتج بلا ملف تسليم، ولا يُتاح تنزيله قبل تأكيد الدفع.
- تذاكر دعم وردود، وتحديثات داخل حساب العميل.
- حفظ ملفات PDF وPNG وJPEG الخاصة بحد 10 ميجابايت للملف و20 مرفقًا للطلب.

## التشغيل المحلي

يلزم Node.js 24 وnpm.

```sh
npm ci
cp .env.example .env
npm run build
npm start
```

افتح `http://localhost:3000`. في PowerShell يمكن استخدام `Copy-Item .env.example .env` بدل `cp`.

يستخدم التطوير SQLite في `DATA_DIR`. لا توجد بيانات عملاء أو منتجات أو حسابات تجريبية في الحزمة. أضف المنتجات الحقيقية وأسعارها وملفاتها من لوحة الإدارة.

## إنشاء حساب الإدارة

قبل التشغيل الأول، ضع في إعدادات البيئة بريدًا جديدًا خاصًا بالإدارة وكلمة مرور قوية بطول 12–128 حرفًا:

```dotenv
BOOTSTRAP_ADMIN_EMAIL=admin@your-domain.example
BOOTSTRAP_ADMIN_PASSWORD=
```

اكتب كلمة المرور في البيئة الخاصة بالاستضافة؛ لا تضعها في GitHub. إذا كان البريد موجودًا كحساب عميل، يرفض الخادم ترقيته تلقائيًا. بعد تسجيل دخول الإدارة، احذف متغيرَي التهيئة من الاستضافة وأعد تشغيل التطبيق. الحساب المحفوظ لا يتأثر. صفحة الإدارة: `/#/admin`.

## الإعداد على Hostinger

استخدم تطبيق Node.js مستقلًا، لا ترفع المجلد `public` وحده: الحسابات والطلبات تحتاج تشغيل `server.js`. المنصة ليست مشروع Hostinger AI Builder.

1. من Hostinger افتح Websites ثم إضافة تطبيق Node.js، واختر المستودع `rfrfmnst-cell/antlaqh` والفرع `main`.
2. اختر Node.js **24**، والإطار **Other**، وجذر المشروع `.`. أمر التثبيت `npm ci`، والبناء `npm run build`، والتشغيل `npm start` أو ملف الدخول `server.cjs` وفق الحقول المعروضة. يستخدم LiteSpeed في Hostinger الدالة `require()` لتحميل ملف الدخول؛ يبدأ `server.cjs` التطبيق باستيراد ديناميكي متوافق مع ملفات ESM والتهيئة غير المتزامنة في `server.js`.
3. أنشئ قاعدة MySQL مستقلة للموقع، ومستخدم قاعدة خاصًا به. لا تستخدم قاعدة موقع آخر.
4. عيّن متغيرات الإنتاج التالية في إعدادات الاستضافة:

```dotenv
NODE_ENV=production
APP_URL=https://your-verified-domain.example
DB_DRIVER=mysql
DB_HOST=your-mysql-host
DB_PORT=3306
DB_NAME=your-database
DB_USER=your-database-user
DB_PASSWORD=
DATA_DIR=/absolute/persistent/private/antlaqh-data
TRUSTED_PROXY_IPS=
```

5. يجب أن يكون `DATA_DIR` مجلدًا دائمًا خارج مجلد النشر وخارج أي جذر عام. تحقق من استمرار محتواه بين عمليات النشر. إذا لم توفر الخطة مسارًا دائمًا مناسبًا، استخدم بيئة Hostinger VPS أو أضف مخزن ملفات خاصًا قبل استقبال مرفقات حقيقية. لا تستخدم `/tmp` للملفات الدائمة.
6. يحدد `APP_URL` أصل الطلبات المقبول؛ يجب مطابقته للدومين النهائي مع HTTPS. يقرأ التطبيق `PORT` الذي توفره الاستضافة.
7. بعد معرفة عنوان الوكيل العكسي الفعلي من إعدادات الاستضافة، ضعه في `TRUSTED_PROXY_IPS` (عناوين IP محددة مفصولة بفواصل). لا تستخدم `*` ولا تثق بكل `X-Forwarded-For`. إعداد الوكيل الصحيح ضروري حتى تطبق حدود المحاولات على الزائر لا على الوكيل المشترك.
8. عيّن حساب الإدارة لأول تشغيل كما في القسم السابق، ثم احذف متغيرات تهيئته.
9. اضبط `BUSINESS_EMAIL` و`BUSINESS_PHONE` بعد التأكد من بيانات التواصل.
10. تحقق من `/api/health` ومن إنشاء حساب وطلب وتجربة الدخول مجددًا بعد إعادة تشغيل التطبيق. اختبر بقاء ملف مرفق بعد إعادة نشر نسخة جديدة، ثم اربط الدومين المملوك فعلًا.

مراجع Hostinger: [إضافة تطبيق Node.js](https://www.hostinger.com/support/how-to-deploy-a-nodejs-website-in-hostinger/)، [ربط MySQL](https://www.hostinger.com/support/connecting-a-hostinger-mysql-database-to-a-node-js-application/).

## الجوال والدفع والإشعارات

- لتفعيل الجوال، عيّن `TWILIO_ACCOUNT_SID` و`TWILIO_AUTH_TOKEN` و`TWILIO_VERIFY_SERVICE_SID` في البيئة، وفعّل الدول المطلوبة في حساب Twilio. اختبر إرسال رمز حقيقي قبل اعتبار الخدمة مفعلة. يوثق العميل رقمه من إعدادات حسابه أولًا؛ بعدها يستطيع الدخول بالرمز. لا يوجد رمز تجريبي مقبول في التطبيق.
- الدفع الحالي **يدوي**. يسجل المسؤول مرجع الاستلام بعد التحقق منه. لا توجد بوابة بطاقات أو تحويل تلقائي أو استرداد بنكي متصل. توصيل بوابة دفع يحتاج تحديد المزود وحساب التاجر وإضافة تكامل موثق وتحقق webhook.
- المستند الحالي **إيصال استلام دفع**، وليس فاتورة ضريبية أو منظومة فوترة إلكترونية معتمدة.
- الإشعارات تظهر داخل الحساب. لم يُربط إرسال البريد أو إشعارات WhatsApp.
- الموافقة على العقد محفوظة في قاعدة البيانات؛ لا تدّعي المنصة وجود توقيع إلكتروني معتمد.
- صفحات الشروط والخصوصية تصف السلوك الحالي؛ أكمل بيانات المشغّل التجارية وسياسات التعامل الفعلية قبل الإطلاق التجاري.

## الاختبارات

```sh
npm test
npm run build
```

اختبارات التكامل تستخدم قاعدة وملفات مؤقتة منفصلة، وتختبر صلاحيات العملاء، CSRF، العقود، تأكيد الدفع المتزامن، حماية الملفات، المنتجات، التذاكر، والخروج وبقاء البيانات بعد إعادة تشغيل الخادم. نجاح اختبارات SQLite لا يثبت صحة إعداد MySQL أو Hostinger؛ يجب التحقق منهما في بيئة النشر.

## بنية الملفات

```text
server.js          واجهات API والتحقق من الصلاحيات وتقديم الواجهة
lib/store.js       تخزين SQLite للتطوير وMySQL للإنتاج
lib/security.js    كلمات المرور والتحقق من المدخلات والملفات
public/            الواجهة والأصول العامة فقط
tests/             اختبارات التكامل
scripts/check.mjs  فحص البناء
.env.example       أسماء متغيرات البيئة دون أسرار
```

حافظ على نسخ احتياطية متزامنة لقاعدة MySQL ولمجلد `DATA_DIR/files`. الملفات وأسرار البيئة والبيانات التشغيلية مستبعدة من Git. المصدر لا يحتوي الحزم القديمة ولا يستورد بياناتها تلقائيًا.

## التصميم والكتالوج الجديد

تتبع الواجهة ألوان شعار إنطلاقة الأصلي، ويظهر الرمز المعزول بخلفية شفافة بجوار الاسم «إنطلاقة للتجارة الإلكترونية». تعتمد الخطوط على -apple-system وBlinkMacSystemFont لخط نظام Apple عند توفره، وSegoe UI على Windows. لا تُضمّن نسخة من خطوط Apple ولا تُحمّل خطوطًا من جهة خارجية.

يشمل الكتالوج 14 خدمة، مع صورة مستقلة وصفحة تفاصيل لكل خدمة والبحث والتصنيف. الصور توضيحية للخدمات وليست صور مشاريع منفّذة أو شهادات عملاء. يمكن اختيار غلاف مناسب لكل منتج رقمي من لوحة الإدارة. لا تُنشأ منتجات للبيع أو أسعار وهمية. تفاصيل الأصول في [دليل الصور](docs/ARTWORK.md).

## مساعد إنطلاقة

المساعد متصل عبر الخادم بـ[OpenAI Responses API](https://developers.openai.com/api/docs/guides/text)، والنموذج الافتراضي [gpt-4.1-mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini). لتفعيل الردود، اضبط OPENAI_API_KEY في البيئة الخاصة ثم أعد تشغيل الخادم. لا تضع المفتاح في الواجهة أو GitHub. يمكن تغيير OPENAI_MODEL إلى نموذج يدعم Responses. حتى يُضاف المفتاح، تعرض الواجهة حالة عدم التفعيل ولا تنتج ردودًا وهمية.

يرسل المساعد رسائل المحادثة والكتالوج العام فقط؛ لا يقرأ ملفات العملاء أو الطلبات أو الحسابات ولا ينفذ إجراءات. يستخدم store:false، والمحادثة تبقى في ذاكرة التبويب فقط ولا تُحفظ في قاعدة المنصة. تُعرض للمستخدم ملاحظة بأن OpenAI يعالج الرسائل.

حدود التشغيل: 8 طلبات لكل عنوان IP خلال 5 دقائق، و40 خلال 24 ساعة، و4 طلبات متزامنة، و100 طلب لكل يوم UTC على مستوى عملية الخادم (قابل للتعديل بمتغير ASSISTANT_DAILY_LIMIT). العدادات في الذاكرة وتُصفّر عند إعادة التشغيل، وليست سقف إنفاق مالي؛ اضبط سقف المشروع لدى المزود كذلك. يجب إعداد الوكيل الموثوق كما سبق إذا كان Hostinger يمرر الطلبات عبر وكيل. تُختبر أخطاء المزود والمهلة وحدود الرسائل بنموذج محاكاة، ويجب اختبار رد حقيقي بعد التفعيل.
